# React-клієнт сайту «Моя компанія»

Окремий клієнтський проєкт (React + Vite), який отримує дані з локального Django-сервера
через JSON API і надсилає на нього скаргу POST-запитом.

## Запуск

1. Django-сервер (з кореня репозиторію):

   ```
   python manage.py runserver
   ```

2. React-клієнт (у папці `client`):

   ```
   npm install
   npm run dev
   ```

3. Відкрити http://localhost:5173/

Якщо Django працює на іншому порту, створіть файл `client/.env.local`:

```
VITE_API_URL=http://127.0.0.1:8001/api
```

## Які запити відправляє клієнт

| Вкладка  | Запит                  | Що повертає Django                    |
|----------|------------------------|----------------------------------------|
| —        | `GET /api/company/`    | назва, слоган, контакти, розділи       |
| Послуги  | `GET /api/services/`   | список послуг                          |
| Команда  | `GET /api/employees/`  | співробітники з відділами              |
| Проєкти  | `GET /api/projects/`   | проєкти з клієнтом і послугами         |
| Скарга   | `POST /api/complaints/`| 201 і номер скарги або 400 з помилками |

Праворуч на сторінці є журнал: він показує кожен запит, код відповіді та час.

## Як це влаштовано

- `src/api.js` — усі `fetch`-запити до Django, адреса API з `VITE_API_URL`.
- `src/useApi.js` — хук: завантаження, помилка, повторити запит.
- `src/components/` — вкладки (Services, Employees, Projects, ComplaintForm) і журнал RequestLog.
- Форма скарги перевіряє поля в React, а потім Django перевіряє їх ще раз тією ж `ComplaintForm`
  і повертає помилки у JSON.
- Клієнт (порт 5173) і сервер (порт 8000) — різні адреси, тому в Django є CORS
  (`api/cors.py`, дозволені адреси в `API_ALLOWED_ORIGINS` у `config/settings.py`).
